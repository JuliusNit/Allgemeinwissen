## Programmiersprachen im Überblick

- Computer verstehen nur **Maschinencode** (Nullen und Einsen); Programmiersprachen sind menschenlesbare Brücken dorthin
- Übersetzung: **Compiler** übersetzt vorab das ganze Programm (C, Rust, Go – schnell), **Interpreter** führt Zeile für Zeile aus (Python, JavaScript – flexibel)

| Sprache | typischer Einsatz |
|---|---|
| **Python** | Einstieg, Datenanalyse, KI, Wissenschaft |
| **JavaScript / TypeScript** | Webseiten und Web-Apps (läuft im Browser) |
| HTML, CSS | Struktur und Aussehen von Webseiten (keine Programmiersprachen im engeren Sinn) |
| **Java, Kotlin** | Android-Apps, große Unternehmenssoftware |
| **C, C++** | Betriebssysteme, Spiele, Geräte, wo Tempo zählt |
| **C#** | Windows, Spiele (Unity) |
| **Swift** | Apps für iPhone und Mac |
| **SQL** | Datenbanken abfragen |
| Rust, Go | sichere, schnelle Systeme, Cloud |

- Grundbausteine fast überall gleich: **Variablen**, Bedingungen (if), Schleifen (for/while), Funktionen, Datenstrukturen
- Paradigmen: imperativ (Schritt für Schritt), **objektorientiert** (Objekte mit Eigenschaften und Methoden), funktional
- Heute schreiben KI-Assistenten viel Code mit – Verstehen, Prüfen und Entwerfen bleiben menschliche Aufgaben

## Verschlüsselung

```gruppen
Symmetrisch
  **ein** Schlüssel zum Ver- und Entschlüsseln (Cäsar-Chiffre, heute **AES**)
  schnell, aber: Wie tauscht man den Schlüssel sicher aus?
Asymmetrisch (Public-Key, 1976/77: Diffie-Hellman, **RSA**)
  **öffentlicher Schlüssel** zum Verschlüsseln (darf jeder kennen)
  **privater Schlüssel** zum Entschlüsseln (bleibt geheim)
  Bild: offenes Vorhängeschloss verschicken, nur der Empfänger hat den Schlüssel
  beruht auf Mathematik, die in eine Richtung leicht, rückwärts extrem schwer ist (große Primzahlen multiplizieren vs. Produkt zerlegen)
Hybrid (Praxis)
  asymmetrisch wird ein symmetrischer Sitzungsschlüssel ausgetauscht, dann schnell symmetrisch weiter
  so arbeitet **HTTPS** (Schloss im Browser), WhatsApp, Signal
```

- **Ende-zu-Ende-Verschlüsselung**: nur Sender und Empfänger können lesen, nicht einmal der Anbieter → Streit mit Behörden („Chatkontrolle“ der EU)
- **Digitale Signatur**: mit dem privaten Schlüssel „unterschreiben“, jeder kann mit dem öffentlichen prüfen, dass es echt und unverändert ist
- Bedrohung durch Quantencomputer → neue **Post-Quanten-Verfahren** (2024 standardisiert)

## Passwörter, Hashes und Passkeys

```kette
Webseite speichert **nicht** dein Passwort, sondern seinen **Hash** | Einweg-Funktion: aus Hash nicht zurückrechenbar
beim Login wird deine Eingabe gehasht und verglichen
**Salt**: Zufallswert pro Nutzer → gleiche Passwörter ergeben verschiedene Hashes
langsame Hashfunktionen (bcrypt, Argon2) bremsen Angreifer beim Durchprobieren
```

- Gute Passwörter: **lang** (Länge schlägt Sonderzeichen), für jeden Dienst **anders** (sonst Credential Stuffing nach Datenlecks), am besten im **Passwortmanager**; regelmäßiges Ändern ohne Anlass empfiehlt das BSI nicht mehr
- **Zwei-Faktor-Authentisierung**: Wissen (Passwort) + Besitz (Handy, Sicherheitsschlüssel)
- **Passkeys** (seit 2022, FIDO-Standard): statt Passwort ein Schlüsselpaar – der private Schlüssel bleibt auf deinem Gerät, entsperrt per Fingerabdruck/Gesicht; der Server kennt nur den öffentlichen → nichts zu stehlen, **Phishing**-resistent (funktioniert nur auf der echten Seite)

> Sicherheit im Netz beruht auf Mathematik: Einwegfunktionen, Schlüsselpaare – und darauf, dass Geheimnisse geheim bleiben.
